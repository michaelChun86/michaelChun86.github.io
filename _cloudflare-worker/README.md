# 2부 — 대시보드에 실데이터 넣기 (선택, 15분)

## 왜 중계 서버가 필요한가

브라우저는 GA4 를 직접 못 읽습니다. 구글이 **서비스 계정 키**를 요구하는데,
그 키를 웹페이지에 넣으면 소스를 여는 누구나 볼 수 있기 때문입니다.

```
관리자 페이지  ──(그냥 요청)──▶  Worker  ──(키로 인증)──▶  GA4
              ◀──(숫자 JSON)──          ◀──(원본 데이터)──
```

키는 Cloudflare 에 보관되어 브라우저로 나가지 않습니다. 전부 무료입니다.

> 달라게임즈용 Worker 를 이미 만들어 두셨다면, **서비스 계정 키는 같은 것을
> 재사용**할 수 있습니다(아래 2-3~2-4 생략). 다만 Worker 자체는 속성 ID 가
> 하나씩만 들어가므로 **새로 하나 더 배포**해야 합니다.

## 1단계 — GA4 속성 ID 찾기

**측정 ID(`G-...`)와 다른 값입니다.** 숫자 9~10자리입니다.

관리(톱니) → **속성 설정** → **속성 세부정보** → 우측 상단 **속성 ID** 복사

## 2단계 — 구글 클라우드에서 키 만들기 (기존 키 재사용 시 생략)

### 2-1. 프로젝트
[console.cloud.google.com](https://console.cloud.google.com) → **새 프로젝트** → 이름 `chun-analytics`

### 2-2. API 켜기
**API 및 서비스** → **라이브러리** → `Google Analytics Data API` 검색 → **사용**

### 2-3. 서비스 계정
**사용자 인증 정보** → **만들기** → **서비스 계정** → 이름 `ga4-reader` → 역할 비워두고 **완료**

### 2-4. 키 내려받기
서비스 계정 클릭 → **키** 탭 → **키 추가** → **새 키 만들기** → **JSON**

> **이 파일이 곧 열쇠입니다. 절대 공유·업로드 금지.**
> 이 저장소에도 넣지 마세요.

## 3단계 — GA4 에 읽기 권한 주기

이걸 빼먹으면 나중에 **403 오류**가 납니다.

GA4 → **관리** → **속성 액세스 관리** → 우측 상단 **+** → **사용자 추가**
→ JSON 의 `client_email` 값 붙여넣기 → 역할 **뷰어** → 추가

> 기존 키를 재사용하는 경우에도 **새 속성에 다시 초대**해야 합니다.

## 4단계 — Cloudflare Worker 배포

1. [dash.cloudflare.com](https://dash.cloudflare.com) 로그인 (무료)
2. **Workers & Pages** → **Create** → **Start with Hello World!** → **Deploy**
3. 이름은 `mc-ga4` 처럼 달라게임즈용과 구분되게 지으세요
4. **Edit code** → 편집기 내용을 전부 지우고 이 폴더의 **`worker.js`** 를 통째로 붙여넣기
5. 우측 상단 **Deploy**

주소가 생깁니다. 예: `https://mc-ga4.your-name.workers.dev`

### 4-1. 변수와 시크릿 넣기

Worker 화면 → **Settings** → **Variables and Secrets**

| 이름 | 종류 | 값 |
|---|---|---|

| `ALLOWED_ORIGIN` | Text | `https://michaelchun86.github.io` |

### 4-2. 확인

브라우저에서 Worker 주소를 그냥 열어보세요. 이런 JSON 이 보이면 성공입니다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `403 ... permission` | 2부 3단계를 안 했거나 이메일 오타. 속성 액세스 관리에서 뷰어로 등록됐는지 확인 |
| `토큰 발급 실패: invalid_grant` | 키가 잘렸습니다. JSON 을 통째로 다시 넣으세요 |
| `속성 ID 미설정` | 변수 저장 후 **Deploy** 를 안 눌렀습니다 |
| `속성 ID 는 숫자여야 합니다` | 측정 ID(`G-...`)를 넣으셨습니다. 2부 1단계의 숫자를 넣으세요 |
| 숫자가 전부 0 | 정상입니다. GA4 는 누적 데이터 반영에 최대 24~48시간 걸립니다 |
| 대시보드에 여전히 샘플 | 2부 5단계 주소를 안 넣었거나 오타. Worker 주소를 직접 열어 JSON 이 나오는지 먼저 확인 |
| 내 방문이 통계에 안 잡힘 | 정상입니다. `analytics.js` 는 localhost 에서 전송하지 않습니다. 배포본에서도 안 잡힌다면 [내 방문을 집계에서 빼기] 가 켜져 있는지 확인하세요 |
| 유입 경로에 `(not set)` / 영문 이름 | 고장이 아닙니다. GA4 가 출처를 판별 못 한 세션입니다(앱 내부 브라우저, 리퍼러 차단, 집계 초기). `worker.js` 가 **미확인** 으로 한글화합니다 |
| 유입 경로 목록을 고치고 싶다 | `worker.js` 의 `SOURCE_NAMES` 에 `"도메인": "표시할 이름"` 한 줄 추가 후 Cloudflare 에 다시 붙여넣고 Deploy |

## 내 방문을 집계에서 빼기

검수하려고 들어간 것까지 방문자로 잡히면 숫자가 오염됩니다. 두 가지를 다 써도 됩니다.

### ① 이 브라우저만 빼기 (기기 단위, 권장)

관리자 대시보드 맨 아래 **"이 브라우저의 방문은 집계에서 제외"** 체크박스를 켜세요.
켜져 있으면 글씨가 보라색으로 바뀝니다.

체크박스를 쓰기 어려운 기기(휴대폰 등)에서는 주소로도 켤 수 있습니다. 한 번만 열면 됩니다.

```
켜기:  https://michaelchun86.github.io/?notrack=1
끄기:  https://michaelchun86.github.io/?notrack=0
```

제대로 켜졌는지 보려면 사이트에서 F12 → 콘솔에
`이 브라우저는 집계에서 제외 중입니다` 가 찍히는지 확인하세요.

- 검수용 PC·휴대폰마다 **한 번씩** 해 두면 됩니다.
- 브라우저 저장소를 지우거나 시크릿창을 쓰면 다시 잡힙니다.
- 관리자 대시보드 자체는 원래 추적 코드가 없어 언제나 안 잡힙니다.

### ② 집·사무실 전체 빼기 (IP 단위)

1. GA4 → **관리** → **데이터 스트림** → 스트림 선택 → **태그 설정 구성**
2. **내부 트래픽 정의** → **만들기** → 규칙 이름 아무거나, IP 주소에 내 공인 IP 입력
   (내 IP 는 구글에 `내 아이피` 검색하면 바로 나옵니다)
3. ★ 여기서 끝내면 안 됩니다 → **관리** → **데이터 설정** → **데이터 필터**
   → `Internal Traffic` 을 **테스트 → 사용** 으로 변경

- 공유기에 붙은 모든 기기가 한 번에 빠집니다.
- 유동 IP 면 주소가 바뀔 때마다 규칙을 고쳐야 합니다.
- 휴대폰 LTE/5G 는 IP 가 달라 빠지지 않습니다. 그건 ①로 처리하세요.

> 이미 집계된 과거 방문은 두 방법 모두 **소급해서 지우지 못합니다.**
> 지금부터 들어오는 것만 걸러집니다.

## 비용과 한도

전부 **무료 범위 안**입니다.

- Cloudflare Workers 무료: 하루 10만 요청 (이 대시보드는 하루 몇십 건 수준)
- GA4 Data API 무료: 하루 25,000 토큰 (한 번 열 때 16건 조회)

Worker 가 결과를 **5분간 캐시**하므로 새로고침을 연타해도 GA4 를 계속 부르지 않습니다.

## worker.js 를 고쳤을 때

이 저장소의 `worker.js` 는 **소스 보관용**입니다. 파일을 고쳐 git 에 올려도
Cloudflare 에는 반영되지 않습니다. 반드시 이 절차를 거쳐야 합니다.

1. Cloudflare → **Workers & Pages** → `michael-chun-ga4` → **Edit code**
2. 편집기 내용을 **전부 지우고** 새 `worker.js` 를 통째로 붙여넣기
3. 우측 상단 **Deploy**
4. Worker 주소를 브라우저로 열어 JSON 이 나오는지 확인

> 결과가 **5분간 캐시**되므로, 배포 직후에는 이전 숫자가 잠깐 더 보일 수 있습니다.

## 개발 메모

- **로컬(localhost)에서는 대시보드가 항상 샘플로 뜹니다.** 정상입니다.
  Worker 의 `ALLOWED_ORIGIN` 이 `https://michaelchun86.github.io` 로 잠겨 있어
  다른 출처의 브라우저 호출은 CORS 에서 막힙니다. 실제 화면은 배포본에서 확인하세요.
- **잠금 화면이 안 사라지면 `[hidden] { display: none !important }` 를 의심하세요.**
  `.lock { display: grid }` 같은 작성자 스타일은 브라우저 기본값인
  `[hidden] { display: none }` 을 항상 이깁니다. 그래서 JS 가 `lock.hidden = true`
  로 감춰도 잠금 화면이 그대로 남아, 비밀번호를 맞게 쳤는데도 로그인이
  안 되는 것처럼 보입니다. `admin.css` 위쪽에 그 한 줄이 있어야 합니다.
